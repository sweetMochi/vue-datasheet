# 02 · 測試環境選型

`2026-09-18` · **人工介入：指定方向** — AI 原本以 happy-dom 為前提推論，由人工指定改用 Vitest browser mode（Playwright）

## 問題

題目只寫「測試至少一支」，沒有指定 runner 或測試環境，這個選擇要自己做

## 實測一：EventSource 在模擬 DOM 環境不存在

| 環境 | `EventSource` |
|---|---|
| `happy-dom` 20.14.5 | ❌ `undefined` |
| `jsdom` 30.1.0 | ❌ `undefined` |
| Node 24.20.0 | ❌ `undefined` |
| Node 24.20.0 + `--experimental-eventsource` | ✅ `function` |
| 真瀏覽器 | ✅ 原生 |

翻原始碼確認 happy-dom 完全沒有相關實作：

```
grep -ril "eventsource" node_modules/happy-dom/lib/   →  無任何檔案
'EventSource' in window                               →  false
```

但缺口很窄，不是「happy-dom 處理不了串流」：

| API | happy-dom |
|---|---|
| `EventSource` | ❌ |
| `structuredClone` | ❌ |
| `fetch` / `ReadableStream` / `TextDecoder` | ✅ |
| `MessageEvent` / `AbortController` / `WebSocket` | ✅ |
| `ResizeObserver` / `IntersectionObserver` | ✅ |

它的 `fetch` 甚至是真串流（伺服器每 100ms 送一筆）：

```
fetch resolve 於 8ms
各 chunk 抵達時間(ms): 9, 117, 226, 335, 443
```

## 判斷依據

影響範圍不只是「測不到 SSE」 — 題目那九項資訊裡有七項的來源都在 SSE 這條線上，一旦 `new EventSource()` 寫在元件裡，那個元件在測試環境會連 `mount()` 都丟例外 — 進度畫面、逐筆渲染、中止、錯誤、必填檢查、候選答案全部連帶測不到

換 DOM 環境解決不了（jsdom 同樣沒有），所以只有三條路：polyfill、跑在真瀏覽器、或把傳輸層抽離

## 人工介入

AI 最初把 Vitest + happy-dom 當成既定前提在分析，沒有標示那是自己的選擇；人工指出題目並未指定測試工具後，才回頭確認原文並攤開所有選項

人工接著指定使用 **Vitest browser mode**，AI 據此實測驗證

## 實測二：browser mode 驗證

`vitest@5.0.1` + `@vitest/browser-playwright@5.0.1` + `playwright@1.63.0`，headless Chromium：

```
>>> EventSource: function EventSource() { [native code] }
>>> UA: Mozilla/5.0 (Windows NT 10.0; Win64; x64) ... HeadlessChrome/153.0.8010.12
```

假後端改成 Vite middleware（真 HTTP、真連線、真斷線），客戶端收第 3 筆後 `es.close()`：

```
>>> close 時已送 3 筆 → 500ms 後 3 筆 / 伺服器偵測到斷線: true
```

附帶收穫 — 樣式走完整 CSS cascade，`getComputedStyle` 拿得到真值：

```
>>> Tailwind text-red-600 計算後: oklch(0.577 0.245 27.325)
```

這讓「必填缺漏是紅色、低把握度是琥珀色」這種視覺層級變成可驗證的

## 結果

- 測試跑在真瀏覽器，不用模擬 DOM
- 不需要 `happy-dom`、`jsdom`、`eventsource` polyfill
- 代價：`npx playwright install chromium` 要下載 114.6 MB
